# 大V画像库方案

> 日期：2026-09-09  
> 状态：**一期已落地（2026-09-09）**  
> 前置：`big_v_profile` / `big_v_opinion`（2026-08-23）、雪球 Playwright 按需抓取（2026-08-25）

仪表盘新页 + 飞书入口：对指定小名单大V建可检索语料和人格卡，按该人视角问答。一期只自动采雪球近期动态；成熟版沿同一管道回灌能翻到的公开历史。

---

## 0. 已锁定原则

1. **对话优先。** 打开模块先选人提问；画像和时间线是素材，不是首页。
2. **精选小名单（约 5–15 人）。** 你登记显示名 + 雪球数字 ID（可从主页 URL 解析）。只跟 `watched=1` 的人。
3. **默认有据，可切推断/扮演。** 有据必须对上原文，对不上就说没谈过；推断按人格卡外推并标「推断」。
4. **一期只自动采雪球。** 公众号 / 微博 / 抖音只记 `source_links`，不抓；粘贴入库留后。
5. **本地语料 + SQLite FTS，不上向量库。** 向量检索（方案 B）以后再说，表结构不堵死。
6. **一块引擎、两个入口。** 仪表盘和飞书都调 `ask_big_v`，飞书不另写扮演。
7. **飞书：口令必进、口语也能进。** `/大V 段永平 ……` 一定走画像库，点名失败回「名单里没有」；`问段永平 ……` / `以林园的视角 ……` 匹配到名单也走同一引擎，匹配不到当普通对话。群聊仍要 @，私聊直接答。
8. **一期只采最近言论；成熟版要尽量全量公开历史。** 同一套去重和入库，只是停下来的条件不同。雪球主页是下拉翻页，不是官方归档：成熟版做到「能翻到的公开动态尽量翻完」，删帖 / 仅自己可见做不到。
9. **先方案、审阅通过后再改代码。**
10. **不自动下单、不把大V观点当交易指令。** 回答是人物视角，不是系统买卖建议。

成功标准：

- 名单里的人，隔几个交易日能看到带全文和链接的新言论；同 URL 不重复。
- 仪表盘选人提问：有据模式能挂日期+链接，或明确说没谈过；推断模式外推处有「推断」标记。
- 飞书 `/大V 姓名 问题` 与口语点名走同一套回答；名单外口令失败提示，口语未点名不误入。
- 采集失败次日可续，不中断其他人；仪表盘能看到上次采集时间 / 新增 / 失败原因。

## 1. 问题重述

现有能力停在「对话里偶尔查一下雪球大V」：

| 现状 | 缺口 |
|---|---|
| `big_v_profile` / `big_v_opinion` 已建 | 仪表盘无入口，没有「以他的视角回答」 |
| `query_big_v` / `big_v_update` | 查胜率/近况，不是扮演 |
| Playwright 按需抓主页+正文 | 无定时名单采集；`view` 只存约 500 字 |
| `big-v-monitor` skill | 飞书不会稳定进「指定人物问答」 |
| 2026-08-25 spec 写明不做定时批量 | 本方案把批量采集做成正式任务 |

要补的是：**可维护的小名单、全文语料、可续跑的采集、人格卡、有据/推断双模式、仪表盘+飞书共用引擎。**

## 2. 总体结构

```
名单（big_v_profile.watched=1）
        ↓
big_v_harvest（增量：最近 N 条；成熟版：backfill 游标往更早翻）
        ↓
big_v_opinion（url 去重，body=全文）+ FTS5
        ↓
人格卡（有新全文或卡片过期约 7 天 → LLM 重压，挂在 profile）
        ↓
ask_big_v(人物, 问题, 模式)
        ↓
   仪表盘「大V画像库」          飞书 @ / 私聊
   选人 + 模式开关             /大V 或 口语点名
```

**本期不做**

- 向量库 / embedding 检索。
- 公众号、微博、抖音自动采集；登录态雪球。
- 飞书粘会话人格（「接下来都用段永平」）。
- 一期就把历史翻完（只留游标和限流，成熟版再开回灌）。
- 把大V观点注入日报/盘中专栏（需要再说）。
- 改现有 `query_big_v` 的「查资料」语义；扮演是新函数。

## 3. 数据

一个人一张 `big_v_profile`，不另建账号表。多平台主页放 `source_links`（JSON）。

`big_v_profile` 增补（`SCHEMA_SQL` + `init_db` 迁移，版本 +1）：

| 列 | 用途 |
|---|---|
| `watched` | 1=进定时采集 |
| `persona_card` | 人格卡 JSON 文本 |
| `persona_updated_at` | 卡片重压时间 |
| `last_harvest_at` | 上次采集结束时间 |
| `last_harvest_new` | 上次新增条数 |
| `last_harvest_error` | 上次失败原因（空=成功） |
| `backfill_cursor` | 已翻到的最旧时间或页位 |
| `backfill_done` | 1=公开时间线翻完 |

`big_v_opinion` 增补 `body TEXT`（全文）。`view` 改为短摘要（标题或正文前若干字），列表用。继续按 `url` 去重。

新建 FTS5：`big_v_opinion_fts`，索引 `topic + view + body`，按 `profile_id` 限定检索。

登记：仪表盘填显示名 + 雪球 ID（或主页 URL 解析出数字）。`id` 仍建议 `xq_{uid}`，与现网工具兼容。

## 4. 采集

任务名 `big_v_harvest`。只处理 `watched=1` 且有 `xueqiu_id` 的人。复用 `invest/data/xueqiu_fetch.py`：主页动态 → 新 URL 拉正文 → 写 `body` + 短 `view`。Playwright **串行**，人与篇之间留间隔。

**一期（增量）**：每人主页最近 N 条（建议 N=15）。库中已有 URL 跳过。雪球主页只展示近期，一期不追全历史。要补旧文：页面提高 N、贴 URL 入库，或等成熟版回灌。

**成熟版（回灌）**：同一任务读 `backfill_cursor`，下拉/翻页往更早走，每人每天限篇数。翻尽标 `backfill_done`。不改问答层：新全文进 FTS，人格卡按现有规则重压。

**时间必须落在机器醒着的窗口。** 现网工作日约 08:30–17:30 唤醒，21:30 跑不到。增量挂在盘后、`evening_report`（17:00）之后，例如 **17:10**，补偿窗口到 17:29:59。单次**时间预算**（建议约 15 分钟）：超时停，游标保留，次日续。首次全名单拉正文可能要若干个交易日才齐。周末若机器开着，可挂在 `weekend`（20:00）多翻几页（成熟版回灌优先用周末）。

失败：单人/单篇失败不中断其他人；WAF/超时写入该人 `last_harvest_error`，次日重试。不在飞书刷采集失败。仪表盘展示每人采集状态。

## 5. 人格卡与问答

人格卡字段（JSON）：口吻、已知立场、常谈赛道、明确反对过什么、自相矛盾处、回答禁区。采集后若有新全文，或卡片超过约 7 天，对该人调一次 LLM 重压。不每天每个人都跑。

`ask_big_v(profile_id, question, mode) -> {answer, citations, mode, empty_reason?}`：

1. 读人格卡（可空，有据模式仍可只靠原文）。
2. 用问题对该人做 FTS，取 Top-K（约 8）条，带日期和 URL。
3. `mode=grounded`（默认）：必须对上命中原文；无命中或相关度不够 → 说明没公开谈过或语料未装满，不编立场。回答附日期+链接。
4. `mode=infer`：卡片 + 能找到的原文；外推处标「推断」。
5. 重名不猜，返回候选让入口反问。

现有 `query_big_v` 继续用于「这人什么风格 / 最近发了什么」，不负责扮演。

## 6. 仪表盘

新页 **「大V画像库」**，插入 `dashboard/nav.py` 的 `PAGES_ORDER`（建议在「观点库」附近；观点库仍是系统交易观点，不要混）。

左侧：watched 名单、语料条数、上次采集、失败原因。可登记新人（名 + 雪球 ID）、停跟。  
右侧：当前人、有据/推断开关、对话。答案下挂引用。语料为空时提示先等采集或贴链接。

不在本页做全市场搜索、不做自动交易按钮。

---

## 7. 飞书

群聊仅 @ 后处理，私聊任意消息，与现网一致。

| 说法 | 行为 |
|---|---|
| `/大V 段永平 茅台怎么看` | 本地规则必进画像库；名单无此人 → 「名单里没有」，列已登记姓名 |
| `问段永平 ……` / `以林园的视角 ……` / `用某某的口吻 ……` | 浅规则抽名字，命中名单 → `ask_big_v`；未命中 → 普通 `run_chat` |
| 话里带「推断」「扮演」 | `mode=infer`，否则 `grounded` |
| 重名 | 反问选哪位 |

`/大V` **不要**先丢进普通闲聊再靠模型自觉调用工具。口语识别放在 `_agent_chat` 之前的本地分流（与盘中报告等意图类似）。CHAT_SYSTEM 补一句：已点名且走了 `ask_big_v` 时保持人物视角，并指向引用。

## 8. 测试

全 mock，不连真实网络、不启真实浏览器。

- 只采 `watched=1`；同 URL 不重复写；`body` 进 FTS，短 `view` 仍在。
- 有据 + 无命中 → 不编造；推断 → 正文含「推断」。
- 人格卡过期/有新文才重压（mock LLM）。
- `/大V` 必进；口语命中进、不命中不进；重名反问。
- 时间预算到点停止且保留游标。
- `test_scheduler_jobs` / `JOB_FUNCS` / `JOB_SLOTS` 同步 `big_v_harvest`。
- `ruff check invest scripts tests` 0 错误。
