## 0. 已锁定原则

继承 2026-09-09 辅助交易完善的全部原则，本期只加一条：

1. 仪表盘是盘后复盘工具，不是盘中盯盘台。
2. **系统是辅助交易，不是量化交易 agent。** 不靠 agent / 信号自动决定买卖。
3. 现有报告骨架成熟，不大改（加节、加列、加素材，不重写 4 点 / 10 节）。
4. Token 不搞极限省钱；**不新增定时 LLM 任务**；不为每条动作调一次模型。
5. 信号引擎继续当输入，不再扩一版规则目录。
6. 盘中仍以核心池为主；池外只带非常明确的线索。
7. 机构纪律层（凯利、双 Agent、比价主链、BCS/VMS、簇预算）保持冻结：代码保留，日常栏目不演进。
8. **保留 AI 复盘**（盘中观点复盘、预案质量复盘）。不用「只记三条操作」替代专栏。
9. 先方案、审阅通过后再改代码。
10. **本期成功标准改为「能下手」**：人打开推送或仪表盘，能看到「这几只该买/卖/等/减、价位到了没有、失效没有」。情报够不够用不再作为本期目标。

成功标准（辅助变强，不是自动化）：

- 22:00 之后能拿出一张**明日动作表**（持仓处置优先，探索票其次）。
- 次日 a7 / b1 对照的是这张表与现价，而不是复读昨夜散文。
- 有止损的持仓，盘中会按同一套价位被盯到（不再 cards 与 trade_plans 各说各话）。
- 复盘 lessons 能在次日生成时被引用，而不是只写在当天日报里。
- 池外发现可以「加入观察」，但不能自动入 core、不能自动下单。

## 1. 问题重述

信号二期已经解决「规则太薄、宇宙太小、投放面太窄」。剩下的断裂在最后一公里：

| 现状 | 对辅助的影响 |
|---|---|
| `plan_gen_llm` 只有 direction / 20 字 picks / 20 字 plans | 盘后预案是专栏摘要，不是下单前 checklist |
| cards 已有 `entry_range` / `stop_loss` / `target`，报告不传 | 最可执行的字段躺在库里 |
| 警戒读 cards，P0 止损读 `trade_plans`，b1 核心表只读池 | 「持仓」三套来源，漏监控 |
| discovery / picks 看过就丢 | 信号越多，手工负担越大 |
| `lessons` / `fixes` 不落库；picks 常无 symbol | 每天读新文章，错误模式不收紧 |
| 凯利冻结后日常只剩总仓上限 | 知道「总仓 50%」，不知道这只怎么处理 |

不是报告写得不好，是 **操作面没有唯一数据源**。`viewpoints source='plan'`、`cards`、`trade_plans`、`candidate_pool` 并行，日常推送只消费其中最弱的那份 JSON。

## 2. 总体结构

继续「一次计算、多处消费」。本期总线是**动作**，信号当输入。

```
已有输入（只读）
  cards(locked/review)     → 价位 / 止损 / 目标 / 证伪
  trade_plans(active)      → 正式纪律计划（若有）
  candidate_pool           → 关注宇宙 + falsify
  trade_signals            → 当日 action（短线）
  viewpoints source=plan   → 昨夜 LLM 操作句（仅补洞，不覆盖价位）
        ↓
合成器  invest/actions/
  compose(date, session)   规则优先，按优先级合并成「每标的一行」
        ↓
落库 daily_actions         按交易日覆盖
        ↓
消费方按入口取子集
  a3 盘后     → 明日动作表（主入口，点 4 旁；专栏仍写）
  a0 盘前     → 今日动作（未消化 + 价位）
  a7 竞价     → 核心表加列：动作 / 距区间
  b1 盘中     → 动作对照表（现价 vs 区间 / 止损）；状态刷新
  仪表盘      → 执行纪律页附表（只读；盘后复盘）
  对话        → d33 run_section
  P0 监控     → 阶段 B：cards 止损与 trade_plans 并轨
```

**明确不做（本期与后续阶段都遵守）**

- 自动交易、自动下单、自动把 discovery 写入 `candidate_pool` core。
- 解冻凯利 / 双 Agent / 比价主链到日常栏目。
- 把 `daily_actions` 写进 `trade_plans`（纪律计划仍人工 / CLI；两套不合并成一张表）。
- 重写 a0/a7/b1/a3 骨架；改 a5/a6；新增大报告。
- 新增定时 LLM；每条动作一次 LLM。
- 仪表盘盘中自动刷新；B2 十秒全量推送。
- 再扩信号规则目录（阈值校准除外）。
- 库里没有账户净值时，不编造股数。

## 3. 数据模型

`SCHEMA_VERSION` 13 → **14**。新表进 `SCHEMA_SQL`，现网 `init_db` 一次。

### 3.1 `daily_actions`（操作面唯一源）

主键 `(date, symbol)`：每个交易日每个标的一行。合成时按 §4 优先级合并，不并排两套操作。

| 列 | 含义 |
|---|---|
| `date` | 该行生效的交易日（盘后生成的是**下一交易日**） |
| `symbol` | 个股代码 |
| `name` | 展示名，可空 |
| `verb` | `buy` / `add` / `hold` / `reduce` / `sell` / `wait` / `watch` |
| `priority` | `1` 必须（止损/证伪） / `2` 计划内 / `3` 信号 / `4` 探索 |
| `source` | 胜出源：`card` / `plan` / `pool` / `signal` / `llm` / `user` |
| `source_ref` | `card_id` / `plan_id` / `signal_id` 等，可空 |
| `entry_lo` / `entry_hi` | 买入/加仓区间；等/持有可空 |
| `stop_loss` / `target` | 价位，可空 |
| `invalid_condition` | 失效条件原文 |
| `position_hint` | 仓位提示文本，可空（见 §4.4） |
| `status` | `pending` / `triggered` / `expired` / `done` / `skipped` |
| `hint` | 对象 + 数字 + 含义一句；**不写「建议买入」口号** |
| `evidence` | JSON：来源列表、信号 id、现价快照等 |
| `src` | 默认 `actions` |
| `updated_at` | 合成或盘中刷新时间 |

查询：`list_actions(conn, date, *, priorities=, verbs=, status=)`。  
缺表 / 缺列：查询返回 `[]` 并打 warning，报告该节省略。

同日再合成：先 `DELETE WHERE date=?` 再 INSERT（与 `trade_signals` 按 session 覆盖同构）。盘中只更新 `status` / `evidence` 里的现价，不改 verb 与价位（价位以盘后合成为准，除非 cards/plans 被人工改过——阶段 B 再做「源变更则重算」）。

### 3.2 `review_lessons`（复盘回灌）

| 列 | 含义 |
|---|---|
| `date` | 复盘发生日（盘后日报日） |
| `kind` | `intraday` / `plan` |
| `body` | 一条 lesson 或 fix，≤80 字 |
| `src` | 默认 `llm` |

主键 `(date, kind, body)` 或自增 id + 唯一索引。次日 `plan_gen` / `compose` 读最近 5 个交易日，去重后注入。  
`viewpoints.review_note` **本期不改**（避免和观点库状态机缠在一起）。

### 3.3 阶段 B 才建

`watch_items`（观察名单，见 §7）。阶段 A 不做。

`cards` / `trade_plans` / `candidate_pool` **不改列**。阶段 A 只读。

## 4. 合成规则

模块建议：`invest/actions/`（`types.py` / `compose.py` / `persist.py` / `format.py` / `query.py`）。  
纯函数 + 读库；auction/intraday 刷新 status 时才用已有行情快照，不在合成器里新开网络（与 `signals.scan` 一样：调用方注入 quotes）。

### 4.1 宇宙

必须入表（priority 1–2）：

- `cards.status IN ('locked','review')`
- `trade_plans.status='active'`
- `candidate_pool.level IN ('core','track')` 且 `out_date IS NULL`

可以入表（priority 3–4，有上限）：

- 当日（或昨夜 close）`trade_signals`：`horizon=short` 且 `severity=action` 且 `subject_type=stock`，上限 **8**
- a3 `picks`（须带 symbol），上限 **3**，verb=`watch`，priority=4

池外 action / picks **不得**写入 `candidate_pool`。只进 `daily_actions`，verb 多为 `watch`。

中线 `quad_*` 不点名个股，**不进动作表**（继续走 a0「市场机会」/ 仪表盘散点）。

### 4.2 优先级（高者胜，同标的只留一行）

1. **证伪 / 破止损** → `sell` 或 `reduce`，priority=1。来源：cards.stop_loss / cards.falsify / trade_plans.stop_loss / pool.falsify_condition。盘后用收盘价判断「已破」；未破则 verb 仍按计划，但 hint 带止损价。
2. **正式计划价位** → `trade_plans` 与 `cards` 都有区间时：**plan 优先**（人明确建过计划）；否则用 card。verb 由区间与「是否已在关注/持仓」推断：有持仓卡且未到加仓区 → `hold`/`wait`；到买入区且无持仓痕迹 → `buy`/`wait`。
3. **昨夜 LLM `plans[]`** → 只补 **hint 与 verb**（持有/减/加映射到 hold/reduce/add）。**禁止覆盖**已有 entry/stop/target。
4. **短线 action 信号** → 无计划行时新建 `watch`（或 `wait`）；已有计划行则写入 `evidence`，不改 verb。
5. **LLM picks** → 仅当该 symbol 还没有行：`watch` + reason/plan 原文。无 symbol 的 pick **丢弃**（见 §5）。

无法推断 verb 时默认 `hold`（已在卡/池）或 `watch`（仅信号/pick）。

文案纪律与信号相同：对象 + 数字 + 含义一句；不写「建议买入」。用 verb 列表达动作，hint 解释条件。

### 4.3 状态机（盘中刷新）

调用方注入 `{symbol: last}`：

| 条件 | status |
|---|---|
| 现价落入 `[entry_lo, entry_hi]` | `triggered` |
| 现价触及或跌破 `stop_loss` | `triggered`（verb 已是 sell/reduce 则保持；否则 hint 标明破止损，**不在阶段 A 改 verb**——避免合成器盘中改写操作） |
| `invalid_condition` 可机读且命中（仅预留：空或非结构化则不判） | `expired` |
| 用户在仪表盘/CLI 标记完成或跳过 | `done` / `skipped`（阶段 B） |
| 其余 | `pending` |

阶段 A：a7/b1 刷新 status 并展示；不要求用户标记 done。隔日新 `date` 自然作废昨日 pending。

### 4.4 仓位提示

库里**没有**账户净值，阶段 A **不算股数**。

若该行来自 card 且有 level + 有效入场中点 + 止损：`position_hint` 写成规则原文，例如 `固定风险 R=0.35%，个股帽 10%`（复用 `invest/discipline/position.py` 的 `LEVEL_RISK` / `LEVEL_CAP` 常量，不算 qty）。  
无卡或缺价位：留空。总仓上限继续走现有 `d9_rating_guide`，不塞进每一行。

解冻凯利不在范围内。

## 5. LLM 怎么用

专栏次数不增加。改变的是**素材和约束**。

### 5.1 生成顺序（a3）

1. 规则 `compose` 出「价位已齐」的草稿（cards / plans / pool / 当日 close 信号）。
2. 把草稿表 + 持仓**完整字段**（代码、收盘、entry、stop、target、falsify）注入 `plan_gen_llm`。
3. LLM 仍出 direction / picks / plans，供专栏可读与质量复盘。
4. **硬约束**：`picks[].symbol` 必填（6 位代码）；没有代码的 pick 合成器丢弃。`plans[]` 必须覆盖草稿里 priority 1–2 的全部 symbol。
5. 合成器二次合并：LLM 只补洞，不覆盖价位。
6. persist `daily_actions`（date=下一交易日）+ 现有 `_persist_plan`（专栏历史保留）。
7. `plan_review_llm` / `intraday_review_llm` 的 `fixes` / `lessons` **同时写入** `review_lessons`。

`_holdings_text` 改为带价位字段。`_persist_plan` 截断 2000 字的问题：动作表已是结构化源，JSON 截断不再影响下手；专栏 JSON 仍可截断。

### 5.2 Prompt 纪律（增量）

现有 `_SIGNAL_CITE` 保留。再加：

- 必须引用动作草稿里的价位；禁止编造止损 / 买入区间。
- 草稿已有 verb 时，`plans[].action` 与之对齐，不要另写一套方向。
- picks 优先落在 hunt / discovery（已有软约束），且必须带 symbol。
- 注入最近 `review_lessons`，避免重复同一类错误。

点 2 / 点 3 专栏结构不动。

### 5.3 优先级展示（报告里写死，不靠模型仲裁）

同一份报告若信号与专栏冲突，读者按表头顺序看：

**持仓处置（priority 1）> 计划内动作（2）> 规则 action（3）> 探索 picks（4）**

格式化函数按此排序。不再并列三套「推荐股」互抢第一眼。

## 6. 各入口怎么用（报告只完善）

### 6.3 a7 竞价

### 6.4 b1 盘中

4 点不动。点 4「预案对照」从复读 JSON，改为：

- 主表：当日 `daily_actions` priority 1–2 + 任何 `triggered`（含池外 watch 已触发）。
- 列：动词、现价、区间、止损、status。
- 昨夜 direction 一句话可留在表下，完整 JSON 不再当正文。

**简洁版**：客观盘面保留；**动作对照表也保留**（这是盘中唯一该看的私有信息）。推演 / 主线专栏仍可按现逻辑在简洁版去掉。  
（若你否决「简洁版也出动作表」，则改回仅完整版——见 §13。）

中线不进 b1。discovery 非 action 不进动作表（已在合成上限里）。

刷新：b1 `render` 注入实时行情，更新 status 后 persist（同日覆盖 status）。失败则只展示库里的 pending。

### 6.5 仪表盘

不加新导航页（阶段 A）。在「执行纪律」页顶部加「动作清单」只读表：默认最近一个有数据的 `date`，可筛 priority / verb / status。  
观点库 / 回测 / 联动网络不改。交易信号页不塞动作表（避免和信号总线混为一谈）。

### 6.6 对话

新小节 `d33_daily_actions`：`render(db_path, date=默认今日)`。`run_section` schema 补上。  
阶段 A **不**加 `create_card` / `record_trade` 工具（YAGNI）。

### 6.7 a4 / a5 / a6

周报可在中线信号节后加一行「本周动作兑现：triggered/expired 计数」，不做个股清单。  
a5/a6 **完全不动**。

## 7. 阶段 B — 三轨合一 + 观察名单

阶段 A 落地并实盘用一周后再做。此处先定口径，避免 A 把后路堵死。

### 7.1 监控并轨

`monitor.check_position_falsify` 在 `trade_plans` 之外，再读 `cards.status IN ('locked','review')` 且 `stop_loss IS NOT NULL`。同标的两源都有止损时 **plan 优先**（与合成器一致），只推一条 P0。

b1 `_core_quotes` 与 a7 对齐：候选池 core/track **并集** locked/review 卡。

不强制「有持仓必有 trade_plans」。卡片止损足够进 P0。`create_plan_from_card` 仍是人工可选。

### 7.2 观察名单（半自动，非自动入池）

新表 `watch_items`：

| 列 | 含义 |
|---|---|
| `symbol` | 代码（PK 或与 `status=open` 唯一） |
| `source` | `signal` / `llm_pick` / `user` |
| `source_ref` | 信号 id / 日期 |
| `reason` | 一句 |
| `status` | `open` / `promoted` / `dismissed` / `expired` |
| `in_date` / `expire_date` | 默认 T+5 交易日过期 |

写入时机（仍不入 `candidate_pool`）：

- 连续 2 个交易日同标的 `verb=watch` 且来自 signal；或
- 用户在仪表盘点「加入观察」（阶段 B UI）；或
- CLI：`scripts/discipline.py watch add`

升级 core/track：**只走现有** `add_to_pool`（硬门槛仍在）。观察名单只是漏斗，不是第二套池。

`candidate_decisions` 继续当审计日志：promote / dismiss 时写一条，仪表盘阶段 B 可展示，阶段 A 不做 UI。

### 7.3 用户标记

`daily_actions.status` 的 `done` / `skipped` 由仪表盘或 CLI 写入。报告只读。不做微信里点按钮（通道能力不够，不新开交互）。

## 8. 阶段 C — 盘中被动 digest
