# 飞书功能实现方式梳理（脚本 / 大模型 / 结合）

> 结论日期：2026-08-21。按代码实际调用链核对（`invest/push/`、`invest/agent/`、
> `invest/report.py`、`invest/pipeline.py`、`invest/scheduler.py`、`invest/intraday.py`、
> `invest/monitor.py`、`invest/scan.py`）。
>
> 总体判断：**主动推送绝大多数是脚本模板（少量 LLM 点缀），交互问答几乎全部走 LLM**。
> 飞书体验的瓶颈集中在 LLM 环节：意图识别每次调用 + 会话 Agent 多轮工具调用 + UZI 5-20 分钟。

---

## 一、纯脚本实现（规则 / 模板 / 数据驱动，不调 LLM）

| 功能 | 入口 / 位置 | 说明 |
|---|---|---|
| 飞书消息收发基础设施 | `invest/push/feishu_push.py` | tenant token 缓存(2h)、发送失败重试、同 key 限频、`send_post` 富文本、`add_reaction` 表情 |
| 飞书长连接接收 | `invest/push/feishu_ws.py` | lark-oapi WebSocket，事件路由/线程化/异常落日志/自动重连 |
| 消息解析与路由 | `feishu_ws._extract_text / _is_mentioned / _handle_event` | text/post 文本提取、三种 Mention 形态兼容、机器人自消息忽略、私聊/群聊/管理员/非管理员分流 |
| 限频与限额 | `feishu_ws._rate_limited / _nonadmin_budget_exceeded` | 报告 30s/人、会话 10s/人；非管理员 100 万 token/日（查 `llm_usage job='group'`） |
| 问候/帮助兜底 | `feishu_ws._is_greeting` + `_HELP_TEXT` | 本地关键词判定，零 token |
| ❤️ 已读表情 | `feishu_ws._handle_event_async` → `add_reaction` | 仅艾特/私聊回；p1+p2 双注册忽略 reaction 事件 |
| 盘前信息早报 8:40 | `report.morning_brief_report` → `pipeline.notify_morning_brief` | 隔夜市场/外围/龙虎榜/板块主线/候选池/宏观速览，全数据模板，**仅发飞书** |
| 收盘扫描 16:00 | `scan.run_scan_and_notify` | 快照对比：新入池/等级变化/评级变化 → `[P1]` 推送 |
| 收盘快照 16:10 | `pipeline.snapshot_close` | 实时源直接写当日收盘价（个股+腾讯指数快照） |
| 环境重评触发 [B8] | `scheduler._premarket` → `macro_gate.check_env_retrigger` | ERP 跨分位/社融拐点/10Y 周变动，规则触发推送 |
| 盘中异动检测 | `intraday.check_core_moves` | 三源轮询 + 阈值规则（主板±3%、创业板/科创±6%），P0/P1 30 分钟限频 |
| P0 监控 | `monitor.run_p0_monitor` | 止损触发/持仓证伪/数据失效（边沿触发状态机） |
| 盘中连板/资金数据采集 | `scheduler._tick_collect_pools` | 涨停池 + 行业主力资金，盘中每 5 分钟落库 |
| 数据滞后门禁 | `scheduler._data_lag_reason / _evening_report` | 日线/指数未到最近交易日 → 不发报告只推原因 |
| LLM 用量告警推送 | `agent/llm.py._maybe_alert_usage` | 单次>2万 / 日累计>50万，脚本核算+推送（数据来自 LLM 调用） |

## 二、大模型解析（LLM 为主，几乎无规则）

| 功能 | 入口 / 位置 | 说明 |
|---|---|---|
| 会话问答（私聊/群 @ 任意问题） | `agents.run_chat` → `agent/llm.py.LLMClient.run` | DeepSeek `deepseek-chat`，max_turns=4，工具调用循环，回答后由模型自选 Skill 并自标注「↘ 已使用 Skill：serenity/youzi/stock_analysis」 |
| 意图识别（是否要盘中实时报告） | `feishu_ws._is_report_request` | **纯 LLM 语义分类**（2026-08-18 去关键词），每次消息都调一次，失败回退帮助提示 |
| 盘前/盘后 Agent 观点 | `pipeline.agent_premarket / agent_after_close` | `run_research` / `run_trade` 双 Agent，输出写 `viewpoints` 表（可复盘） |
| 盘中异动 LLM 归因 | `intraday._attribute` → `run_trade` | 异动时一句话归因（≤50 字），与发送同限频（2026-08-21 修复爆 token） |
| 矛盾仲裁 | `agent/arbiter.py` | 方向冲突观点 LLM 仲裁并存档分歧 |
| 消息面提炼 | `report._news_block` | 财联社电报素材 → LLM 挑重要消息+一句话理由（失败回退直列） |
| 重点行业一句话意见 | `report._focus_industries_block` | 四维度数据 → LLM 汇总意见（失败只出数据） |
| 联网检索 | `agent/web_tools.py`（web_search/web_fetch，已注册工具） | 必应 cn 无 key 检索；LLM 决定何时用 |
| UZI 深度分析流水线 | `agent/skill_runner.py` → `tools/hermes_skills/UZI-skill/.../run.py` | subprocess 跑 447 文件流水线：脚本抓多维数据 + **LLM 多轮分析** → HTML 报告 |

## 三、脚本 + 大模型结合（混合链路）

| 功能 | 脚本部分 | LLM 部分 | 链路 |
|---|---|---|---|
| **@机器人/私聊消息全链路** | 路由、限频、限额、@检测、问候、ack、详细版关键词（`feishu_ws._agent_reply`） | 意图识别 → 会话回答 | 脚本分流 → LLM 判定 → 脚本限频/发消息 |
| **盘中实时报告（"来一份盘中报告"）** | 报告全文模板（`report.intraday_report`：核心池行情/连板梯队/资金主线/板块异动/龙虎榜/温度仓位/操作建议，全部脚本） | 触发它的**意图识别**是 LLM；`_action_guide` 是规则非 LLM | LLM 判定意图 → 脚本生成+发送 |
| **盘后日报 22:00** | 框架与大部分小节（`report.daily_report`：宏观/温度/仓位/评级/情绪/板块/强度榜/异动/候选池/持仓警戒/统计） | 消息面提炼 + 重点行业意见 + Agent 复盘节（读 `viewpoints`，由 Agent 产生） | 脚本搭框架、LLM 填 2-3 节 |
| **周报（周日 20:00）** | 框架（中线强度/低估值候选/宏观/评分统计） | 消息面提炼（近 3 日）+ 周度观点节 | 同上 |
| **盘前清单 8:30** | 模板（仓位/评级/温度/风格/环境重评） | 「关注方向」节 = `agent_premarket` 输出 | 脚本模板 + Agent 内容 |
| **盘中异动推送** | 阈值检测 + 限频 + 推送（`intraday`） | 首条 P0 附 LLM 一句话归因 | 脚本检测 → LLM 归因 → 脚本推送 |
| **UZI 深度分析交互** | 关键词触发（"深度分析/uzi"）、60s ack 限频、异步线程、完成后回发原会话（`feishu_ws._is_skill_request / tools.run_skill` sink） | run_skill 流水线内部多轮 LLM 分析 | 脚本调度 + 外部流水线（LLM 密集） |
| **非管理员 token 限额** | 脚本核算当日 `llm_usage job='group'` 并拦截 | 用量数据由 LLM 调用累计 | LLM 消费 → 脚本记账 → 脚本拦截 |

## 四、从"体验差"角度的观察（供优化参考）

1. **交互链路里 LLM 节点多且串行**：一条普通消息 = 意图识别(1 次 LLM) + 会话 Agent(最多 4 轮、每轮可多次工具调用)，DeepSeek 单次 1-5k token、网络往返秒级，体感就是"慢/转圈"。
2. **意图识别用 LLM 且每次必调**（`_is_report_request` 对每条消息都跑），仅"要不要报告"这类二分类本可用脚本关键词/本地模型，当前是纯语义换来的成本与延迟。
3. **UZI 深度分析 5-20 分钟**是预期内长任务（已做异步 ack + 完成后回发），但 medium/deep 档在飞书里体感接近"没回应"。
4. **定时报告 LLM 点缀节失败会静默回退**（消息面直列素材、重点行业只出数据），报告不阻断——这是优点，但也是"看起来不像 AI 总结"的原因。
5. **盘中异动归因已限频**（2026-08-21 与发送同限频），曾爆 token 的问题已修。
6. 若目标是提升飞书体验，优先优化点：意图识别降级为脚本关键词+LLM 兜底、会话 Agent 减少工具轮数/预热常用结果、报告类消息考虑缓存 LLM 小节（按日 key）。
