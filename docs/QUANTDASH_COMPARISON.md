## 一、能力对照

| quantdash 特性 | 本系统现状 | 差距与建议 |
|---|---|---|
| **情绪周期**（冰点/启动/主升/退潮） | ✅ 有 market_emotion（涨停/炸板/连板高度）+ 温度；但**无情绪周期阶段判定** | 🔧 **落地情绪周期状态机**（用涨停家数/连板高度/炸板率 → 四阶段），供日报/盘前引用（见下） |

| **策略选股** | ✅ 候选池+硬门槛+卡片+发现器 | ✅ 已覆盖且更强（有过错价必要条件） |

**核心差距只有 1 项：情绪周期阶段判定**（quantdash 有，本系统只有情绪原始数据没有阶段定位）。

## 二、落地改进：情绪周期状态机

### 2.1 设计

基于已有 `market_emotion`（limit_up_count 涨停数 / max_lianban 最高连板 / zhaban_rate 炸板率）判定四阶段：

| 阶段 | 判定逻辑（可配置阈值） |
|---|---|
| 冰点 | 涨停数 < 40 且 最高连板 ≤ 3 且 炸板率 > 40% |
| 启动 | 涨停数 40-80 且 最高连板 ≤ 4 且 炸板率 25-40% |
| 主升 | 涨停数 > 80 且 最高连板 ≥ 5 且 炸板率 < 25% |
| 退潮 | 涨停数从高位回落（较 3 日均值下降 >30%）或 炸板率 > 50% |

### 2.2 落点

- 新模块 `invest/quant/emotion_cycle.py`：`emotion_cycle(df) -> 阶段 + 依据`；
- 结果写入 `quant_temperature` 扩展列或独立 `market_emotion.cycle` 列；
- 日报/盘前报告引用：`情绪周期: 主升（涨停98 连板6 炸板率18%）`；
- 与 youzi-trading skill 的"情绪周期定位"打通（游资视角）。

### 2.3 测试

合成多日情绪数据验证四阶段判定边界。

## 三、可选改进（按需）

1. **自研 MCP server**：把本系统查询（温度/强度/候选池/情绪周期）封装成 MCP，供 Hermes/Codex 统一调用——与已装的 akshare-tools 互补（它查外部数据，我们查自研库）。
2. **盘前计划增强**：引入情绪周期后，盘前报告增加"今日操作基调"（冰点试错/主升持股/退潮防守）。

## 四、结论

quantdash-ai-stock 与本系统 90% 能力重叠（且本系统在风控/纪律/复盘上更深），
**唯一实质性缺口 = 情绪周期阶段判定**。优先落地该项（🔧 高价值、纯代码、可单测），
MCP 自研 server 为可选增强。
