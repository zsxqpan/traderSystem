# 短线交易信号引擎 · 落地说明

> 日期：2026-09-03
> 状态：代码已落地（工作区未 commit）
> 对应方案：Cursor plan「交易信号提示方案」（只定方案阶段的结论；本文记录随后实际改了什么）
> 前置：竞价报告 a7 / 盘中 b1 / 盘后 a3 已 skill 化；比价在 `invest/discipline/spread.py` + `auto.py`；D31 杀猪盘是「scan → 落库 → 小节复用」的模板

---

## 1. 改动背景

现有告警和榜单偏「绝对涨跌」和「绝对成交量」，交易时很难直接用：

| 现有能力 | 缺口 |
|---|---|
| a7 高开榜、绝对量放量榜、连板竞价、热门板块核心 | `fetch_batch_quotes` 已有竞价量，表格不展示、也不和昨量比 |
| 盘中异动（`invest/intraday.py`） | 只盯 core 较昨收 ±3%/±6%，不看量 |
| D18 异常波动 | 只有量比≥2 / 振幅 / 影线，没有缩量；且扫的是日线而非池 |
| 涨停池、最高板、炸板率、D23 收盘广度 | 没有晋级率、板块内空间、盘中广度统一口径 |
| 比价 `spread_analysis` | 1–5 年价格/PE 分位；量能只作入池 ADV 硬门槛，时间尺度与短线不同 |

库里原先没有通用 `trade_signals` 表。最接近的复用模板是 D31：规则扫描 → 结构化命中 → 落库 → 报告/推送取用。

需求来源：希望把「竞价保量、关注票极致缩量、板块核心集体高位放量、板块内异动/空间高度与广度」变成**可复用的规则产物**，而不是在每份报告里各写一套阈值。

---

## 2. 目的

1. **一次计算、多处消费**：规则引擎算出信号后，a7 / b1 / a3 / 盘前一行 / 比价 overlay 共用，阈值不漂。
2. **报告里能直接读结构**：谁、什么量价结构、观察还是回避；不再从绝对量榜和 ±3% 异动里猜。
3. **比价只旁路提示**：短线状态（T+0～T+5）不污染 3–5 年主价差和入池门槛。
4. **失败不阻断报告**：行情拉取或单条规则失败 → 该规则空列表，报告继续。

成功标准：交易日报告能读到可执行的量价结构，而不是再从榜单里猜。

---

## 3. 方案要点（已按此实现）

推荐路径：**统一信号引擎 + 报告按会话消费 + 比价 overlay**（对齐 D31）。不在各报告内各写规则，也不只升级 D18/B2/a7 榜单（补不了集体放量 / 空间高度广度）。

### 3.1 扫描宇宙（分层，不全市场扫缩量）

- **监控层**：`candidate_pool` 的 core+track + `cards` locked/review。
- **热门板块核心层**：昨涨停按东财行业聚合，每板块成交量最大 1–3 只（复用 a7 `_hot_core_stocks` 思路，现委托 `universe.hot_sector_cores`）。
- **市场结构层**：`limit_up_pool` + `market_emotion`（高度/广度/晋级），不扫全市场个股 K 线。
- 全市场只保留已有榜单（高开/低开/绝对放量）当发现器，不进精确规则。

### 3.2 会话与信号

| 会话 | 主要进 | 规则 |
|---|---|---|
| `auction`（09:25） | a7 | 竞价保量、竞价缩量分歧、连板高开率、最高板折价 |
| `intraday` | b1 | 极致缩量（时间修正）、高位放量、板块集体高位放量、板块内偏离、空间高度/晋级、广度/炸板；ETF 大资金仅在调用方注入 `etf_quotes` 时进总线（b1 点1 已有 ETF 节，默认不重复） |
| `close` | a3 | 同一套盘中规则改用日线量比（不必时间修正），作兑现/证伪事实 |

分级：`info` 备查 / `watch` 加粗含义 / `action` 置顶。展示：单份最多 **8** 条，action 优先；同类按 `(id, subject)` 去重。无命中整节省略。文案有数字、对象、含义一句，不写「建议买入」。

### 3.3 明确不做（本期仍不做）

- 全市场极致缩量扫描、每条信号调 LLM、自动入池/自动交易。
- 改 `spread_analysis` 主价差定义、把短线量能写进 `mispricing_necessary` / `hard_gate_check` ADV。
- 周报/月报/年报堆日内信号；盘前 a0 不大段新开（只一行「昨日 action 未消化」）。
- 一期把信号接进 B2 10 秒推送（限频和分级未想清楚）。
- 相对昨竞价保量（`今竞价量/昨竞价量≥0.8`）：表 `auction_snapshots` 已建，规则二期再写。东财 f50 竞价量比不可用。

## 4. 实际落地形状

### 4.1 引擎 `invest/signals/`

| 模块 | 职责 |
|---|---|
| `types.py` | `Signal(id, name, session, severity, subject_type, subject, hint, evidence)` |
| `thresholds.py` | 全部阈值常量（见 §5） |
| `timeutil.py` | 交易已过时段比例；09:35 前跳过量能规则 |
| `bars.py` | 昨量 / 5 日均量 / 20 日高 / 近 5 日涨幅；`is_20cm` |
| `universe.py` | `watch_symbols` / `yesterday_zt` / `hot_sector_cores` / `lianban_map` |
| `rules.py` | 纯函数规则（注入行情快照 + 日线统计） |
| `scan.py` | `scan(conn, session, ...)` 编排；`quotes is None` 且 auction/intraday 才拉腾讯批量；`etf_quotes is None` 则不拉 ETF |
| `format.py` | `pick_signals` / `format_signals` / `signal_section` / `tags_for` / `undigested_actions` |
| `persist.py` | 写入 `trade_signals`、`auction_snapshots`；同日同会话先 DELETE 再 INSERT |

入口：`scan()` 返回已截断的展示列表；`persist=True` 时落库的是**全量命中**（overlay 不丢未进 TOP8 的标的），报告仍只展示 8 条。`scan_db(db_path, session)` 失败返回 `[]`。

报价涨跌幅约定与 `fetch_batch_quotes` 一致：**百分点**（`1.2` = +1.2%）。

### 4.2 小节与报告

- 新小节 `d32_trade_signals`：`render(db_path, session=auction|intraday|close)`，给报告 `uses` 和对话 `run_section`。
- 报告 skill 仍是薄组装：各自 `scan_db` 一次，插入独立「交易信号」节；核心关注表加「信号」列。
- LLM prompt（`_intraday_llm` / `_daily_llm`）只注入已算摘要，**禁止模型自己发明保量/缩量**。
- **render 无副作用不落库**；落库只在 `pipeline.notify_auction` / `notify_after_close`（`persist=True`）。

### 4.3 比价 overlay

`auto_factor_score` 读该标的最新 `trade_signals`，追加 `role=背景`、`score=0` 的因子。`factor_score` 对背景权重强制为 0，总分不变。不改 `spread.py`、不改入池 ADV。

### 4.4 Schema

`SCHEMA_VERSION` 11 → **12**。新表进 `SCHEMA_SQL`（`CREATE TABLE IF NOT EXISTS`，现网需再跑一次 `init_db`）：

**trade_signals** PK=`(date, session, signal_id, subject)`

| 列 | 含义 |
|---|---|
| date / session | 交易日；auction / intraday / close |
| signal_id | 如 `auction_keep_vol`、`shrink_extreme` |
| subject_type / subject | stock / sector / market / etf + 代码或板块名 |
| severity / name / hint | 分级、中文名、一句含义 |
| evidence | JSON 证据数字 |
| src | 默认 `signals` |

**auction_snapshots** PK=`(date, symbol)`：竞价价/涨幅/量/额，供二期「相对昨竞价保量」。

## 5. 阈值初值（`thresholds.py`，实盘两周再校准）

| 常量 | 值 | 含义 |
|---|---|---|
| `KEEP_VOL_ZT` | 3% | 连板/昨涨停：竞价量 / 昨全天量 |
| `KEEP_VOL_WATCH` | 2% | 普通关注票保量 |
| `KEEP_AMOUNT` | 2000 万 | 竞价额并列条件 |
| `SHRINK_DIVERGE` | 1.5% | 高开但量比过低 → 缩量分歧 |
| `SHRINK_EXTREME` | 0.40 | 时间修正量比 ≤ 此为极致缩量 |
| `HIGH_VOL_RATIO` | 2.0 | 高位放量 |
| `HIGH_NEAR` | 3% | 现价在 20 日高以内 |
| `RET5_HIGH` | 15% | 近 5 日涨幅视为高位 |
| `LIANBAN_HIGH` | 2 | 连板数视为高位 |
| `COLLECTIVE_MIN` | 3 | 集体信号最少样本；不足不出 |
| `COLLECTIVE_SHARE` | 60% | 核心中同时高位且量比≥1.8 的比例 |
| `COLLECTIVE_VR` | 1.8 | 集体放量量比 |
| `OUTLIER_PCT` | 4.0 | 相对板块中位数偏离（百分点） |
| `OUTLIER_PCT_20CM` | 6.0 | 20cm 标的放宽 |
| `LADDER_OPEN_STRONG` | 80% | 连板高开率 info |
| `LADDER_OPEN_WEAK` | 40% | 连板高开率 watch |
| `BREADTH_SHIFT` | 30% | 涨停家数相对 3 日均 |
| `ZHABAN_HOT` | 40% | 炸板率警戒 |
| `SKIP_BEFORE` | 09:35 | 此前不报缩量/放量 |
| `DISPLAY_LIMIT` | 8 | 单份报告最多条数 |

竞价保量一期用 **昨全天量**（腾讯 `vol` / `daily_bars.volume`），不用东财 f50。

## 9. 上线注意

1. 对真实库跑一次 `init_db`（或等价 `PRAGMA user_version` 升级），否则 `trade_signals` / `auction_snapshots` 不存在，overlay 和盘前「未消化」静默为空。
2. 竞价/收盘推送任务会各多一次 `scan`（带 persist）；报告预览/对话 `run_section` 不写库。
3. `hot_sector_cores` 会调 `fetch_industries`（东财行业）；失败则板块归「其他」，集体信号可能不出——符合「样本不足不出」。
4. 盘中广度只用涨停池，不新造全市场涨跌家数接口。
