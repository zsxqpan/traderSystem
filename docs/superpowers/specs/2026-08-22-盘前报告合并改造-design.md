# 盘前报告合并改造 · 设计文档（A1 + A2 → 单一盘前报告）

## 1. 目标

把 A1 盘前清单（8:30）与 A2 盘前信息早报（8:40）**合并为一个「盘前报告」**（8:40 推送，
用户视角本就是同一东西），并按其 6 点要求改造：

1. 隔夜外围详情（新增日韩）+ LLM 解读外围对 A 股影响；
2. 涨停异动监控（停牌/风险提示/异动监控/暴雷）+ 精简风险提示；
3. 上一交易日收盘 → 今晨消息汇总（宏观/个股/市场外，市场关注度高即收，如"牛来电影破圈"）
   + 精简影响解读与机会提示；报告末尾独立宏观模块删除并纳入此处（宏观仅在有变化时提示）；
4. 删除：龙虎榜净买入排行、指数强弱榜、板块主线（归盘后日报）；关注方向(Agent)与今日关注清单
   大幅简化（仅结论，删依据/失效条件/宏观背景/板块主线）；开头温度等不重复；
5. 排版：适合表格的数据用**飞书卡片表格**；AI 习惯的 `*星号*` 改为加粗（仅飞书生效）；
6. A1/A2 合并（本设计即合并方案）。

## 3. 报告结构（最终）

```
【A股投资系统 · 盘前报告】          数据截至: …
【隔夜外围】(表格) 美股三指|A50|原油|黄金|白银|USDCNY|日经225|韩国KOSPI（失败项省略）
【外围影响·LLM解读】 2-4 句（外围方向对今日 A 股风格/板块的传导）
【市场温度】 36/100 → 偏冷…（沿用）
【仓位/评级】 建议总仓位上限 50%（可进攻）｜宏观=… 市场=…（一行）
【市场风格】 小盘强于大盘…（一句话）
【今日关注】 Agent 结论列表（仅结论，每条一行，删依据/失效条件/宏观背景）
【涨停异动监控】(表格) 停牌 / 风险提示 / 异动监控 / 暴雷（业绩雷·司法雷·黑天鹅）
  附：精简风险提示（LLM 一句总括）
【消息汇总】 宏观（仅变化时）｜个股｜市场外 —— 每条消息 + 一句影响/机会解读
```

**删除项**：龙虎榜净买入、指数强弱榜、板块主线、报告末尾独立宏观模块、末尾仓位、
Agent 关注方向的宏观背景/依据/失效条件、与开头重复的温度展示。

## 4. 技术方案

### 4.1 Skill 结构
- **删除** `reports/a1_premarket.py`、`reports/a2_morning_brief.py`（Skill id 同步注销）；
- **新增** `reports/a0_premarket.py`（盘前报告，合并版）：render 返回**结构化 dict**
  （`{"sections": [{"type": "text"|"table", ...}]}`），由发送层按通道渲染；
- **新增小节 skill**（sections/）：
  - `d24_global_snapshot`：外围数据（含日韩，东财 push2delay 扩展进 global_snapshot）
  - `d25_overnight_analysis`：LLM 外围解读
  - `d26_market_watch`：涨停异动监控（停牌+风险提示+暴雷，电报+LLM）
  - `d27_news_digest`：消息汇总（宏观/个股/市场外 + 影响解读）
- Runner 扩展：`run()` 保持返回 str；新增 `run_structured(id, **params)` 允许返回
  `str | dict`（仅 a0 用），参数校验逻辑复用。

### 4.2 数据层
- `invest/data/global_snapshot.py`：`fetch_global_snapshot()` 扩展日韩（东财 push2delay，
  失败 None → 渲染省略）；新增 `global_snapshot_rows()` 返回表格行（名称/涨跌幅/方向）。
- 停牌：`invest/data/` 新增轻量函数 `fetch_halt_list()`（akshare stop_em，重试 1 次，
  失败返回 []）；停牌数量少时列"停牌 N 家（代码+名称）"。
- 暴雷/风险提示/异动监控：电报素材截断 6000 字 → LLM 筛选（一次调用随消息汇总做）。

### 4.3 LLM 环节（2 次调用，job='premarket'，计入 llm_usage 告警体系）
1. `overnight_analysis`：输入外围数据行 → 输出 2-4 句解读（失败 → 省略该节）；
2. `news_digest + market_watch`：输入电报素材 → 输出 JSON
   `{"risk_items": [{symbol,name,kind(停牌/风险提示/异动监控/业绩雷/司法雷/黑天鹅),event,impact}],
     "news": {"macro": [{title,impact}], "stock": [...], "market_outside": [...]},
     "macro_changed": true|false, "risk_summary": "一句话风险提示"}`
   JSON 解析失败 → 回退直列素材（与现状 _news_block 一致）。
   宏观仅 `macro_changed=true` 且 macro 非空时展示。

### 4.4 发送链路（飞书卡片表格 + 多通道渲染）
- `feishu_push.py` 新增 `send_card(receive_id, receive_id_type, card_json)`：
  msg_type=interactive，卡片 2.0 协议；**表格用卡片 table 组件**（实现时按飞书开放平台
  卡片 2.0 table 组件官方 JSON 构造；构造失败 → 回退 post/text，不阻断推送）。
- 渲染层 `invest/push/render.py`（新）：
  - `render_feishu(struct) -> card_json`：文本节 → div/lark_md（**加粗** 生效、去星号）；
    表格节 → table 组件；
  - `render_plain(struct) -> str`：企微/微信通道用（表格转紧凑行 `名称 涨跌幅`，去星号
    保留原文本，无加粗）。
- 通道接线：Notifier 增 `send_premarket(struct)`：飞书=卡片；企微=现有 text（渲染纯文本）；
  微信=iLink（纯文本）。其他报告 skill 不受影响（仍 send_text）。

### 4.5 调度器 / OS 计划任务
- `scheduler._premarket`（08:30）：**保留** collect+quant+agent_premarket+env_retrigger，
  **删除** `pl.notify_premarket(db, text)` 调用（数据准备任务，不再发 A1）；
- `scheduler._morning_brief`（08:40）：改为生成合并盘前报告并推送
  （`pipeline.notify_morning_brief` → runner a0 → 结构化 → 分通道发送）；
- `JOB_FUNCS` 的 job 名与时间**不变**（premarket 08:30 / morning_brief 08:40），
  只改内部实现 → OS 计划任务（schtasks）**无需改脚本**，重装 `install_os_tasks.ps1` 应用新代码即可；
- 韩国 KOSPI 数据源拿不到时该列省略（Q2 用户确认）。

### 4.6 报告 skill 删除后引用清理
- `pipeline.notify_premarket` 删除；`notify_morning_brief` 改为调 a0 并分通道发送；
- `report.py` 的 `premarket_report` / `morning_brief_report` **保留**（作为 legacy，测试
  `test_morning_brief.py` 不破），标注"已被 a0_premarket 取代"；A2 内被删模块（龙虎榜/
  板块主线等模板段）保留在函数内但不再被调用。

## 5. 测试策略

- `tests/test_skills.py` 更新：注册表数量（30 - 2 + 5 = 33）；a0 在 reports 列表；

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 飞书卡片 table 组件 JSON 细节 | 实现时按官方文档构造；失败回退 post/text，不阻断 |
| 东财 akshare 停牌接口网络不稳 | best-effort（重试 1 次 + 失败省略列）；电报+LLM 是停牌外的补充来源 |
| LLM JSON 输出解析失败 | 解析失败回退直列素材/省略节（沿用现状回退模式） |
| 韩国/日本数据拿不到 | 列省略（用户已确认韩国可不发） |
| 多通道渲染不一致 | 飞书=卡片（表格/加粗）；企微/微信=纯文本（表格转行、去星号） |
| 合并后 8:40 生成耗时（LLM 2 次调用） | 素材截断 6000 字；LLM 失败快速回退；不阻塞推送 |
